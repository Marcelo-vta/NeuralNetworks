    2. Perceptron

    This report trains one hand-written perceptron on two datasets. The first is linearly separable (Exercise 1), the second has heavily overlapping classes (Exercise 2). The aim is to show why the algorithm converges on the first and how it fails on the second. Statement: Exercises → 2. Perceptron (2026.2).

    Re-running. From the repository root, run python docs/exercises/perceptron/code/main.py. It takes about 25 s on a laptop CPU. The script prints every number quoted below, one labelled line each ([Ex1 C] final w = …), and rewrites figures/fig1.png … fig6.png. Two runs give identical output.

    Seed policy. main.py creates the report's single generator, rng = np.random.default_rng(42), once. It passes that generator to Exercise 1 and then to Exercise 2, in statement order. The only random draws are the two datasets (2 × 1000 points plus one shuffle each) and the two initial weight vectors w0. No other module creates randomness.

    Implementation approach and challenges

    Approach. The model is the Perceptron class in code/perceptron.py. It uses only NumPy and contains the step activation, prediction, the error-driven update and the training loop. It is written once and used unchanged by both exercises. train() accepts an optional hook, on_update(model, epoch, i, error), called right after every actual update. Exercise 2 plugs the pocket algorithm into that hook (a Pocket object), so not one line of the class changes between exercises. A second hook, Tracer, only records (epoch, sample, error, w, b). I use it for the update counts and boundary positions in the analyses. No scikit-learn appears anywhere, neither as a model nor as a utility.

    Challenges and decisions.

    1. Pocket without editing the class. The statement requires the Exercise 1 implementation to be reused unchanged. The hook solves this: the pocket copy lives outside the class.
    2. Making "changing nothing else" exact. w0 is drawn once in Exercise 1 and passed to both the \(\eta=0.01\) and the \(\eta=1.0\) runs. Both runs therefore share data, sample order, w0 and b0 = 0.
    3. Sample order. The generator produces all class-0 points and then all class-1 points. The data are shuffled once with rng right after generation, and every epoch visits the samples in that fixed order. This choice turned out to matter a lot in Exercise 2 (see 2-D1).
    4. A one-epoch convergence leaves Figure 3 almost empty. Exercise 1 converges inside epoch 1, so the accuracy curve has only three points. Figure 3 therefore has a second panel with the cumulative number of updates, which is the quantity item D1 asks about.
    5. My numbers differ from the statement's reference values (≈50 % final, ≈73 % best line). Before accepting them, I checked them against a fine scan of straight lines (a NumPy-only diagnostic, no training). On this sample no line beats 70.80 %, so the pocket result (70.70 %) is optimal to within 2 samples out of 2000, not a bug. The final-weights gap is explained in 2-D1.

def out(tag, text):
    """Print one labelled result line; every number quoted in the report comes from here."""
    print(f"[{tag}] {text}")


def fmt_vec(v, nd=4):
    return "[" + ", ".join(f"{x:.{nd}f}" for x in v) + "]"


def make_two_gaussians(rng, mean0, mean1, cov, n_per_class):
    """Draw n_per_class 2-D points per class from N(mean_k, cov); return shuffled (X, y).

    X has shape (2 * n_per_class, 2); y holds the labels 0 / 1 as integers.
    """
    X0 = rng.multivariate_normal(mean0, cov, size=n_per_class)  # class 0 cloud
    X1 = rng.multivariate_normal(mean1, cov, size=n_per_class)  # class 1 cloud
    X = np.vstack([X0, X1])
    y = np.concatenate([np.zeros(n_per_class, dtype=int), np.ones(n_per_class, dtype=int)])
    # The draw above lists all class-0 points before all class-1 points. Shuffle ONCE
    # (with the same rng) so the online perceptron does not see 1000 zeros and then
    # 1000 ones; training then visits the samples in this fixed order every epoch.
    order = rng.permutation(len(X))
    return X[order], y[order]


def describe_data(tag, X, y):
    """Print the sample mean / covariance of each class (sanity check of the parameters)."""
    for k in (0, 1):
        Xk = X[y == k]
        cov = np.cov(Xk.T)
        out(tag, f"class {k}: n = {len(Xk)}, sample mean = {fmt_vec(Xk.mean(axis=0), 3)}, "
                 f"sample cov = [[{cov[0, 0]:.3f}, {cov[0, 1]:.3f}], [{cov[1, 0]:.3f}, {cov[1, 1]:.3f}]]")
    out(tag, f"mean ||x|| over all points = {np.linalg.norm(X, axis=1).mean():.3f}")


# ----------------------------------------------------------------------------- hooks and diagnostics
class Tracer:
    """on_update hook that only RECORDS: (epoch, sample index, error, w1, w2, b) per update.

    It never changes the model, so a run with a Tracer follows exactly the same
    trajectory as a run without one.
    """

    def __init__(self):
        self.rows = []

    def __call__(self, model, epoch, i, error):
        self.rows.append((epoch, i, error, model.w[0], model.w[1], model.b))

    def array(self):
        return np.array(self.rows, dtype=float).reshape(-1, 6)


def state_accuracies(rows, X, y, chunk=2000):
    """Full-dataset accuracy of the weights stored after every update (vectorized)."""
    accs = []
    for s in range(0, len(rows), chunk):
        W, B = rows[s:s + chunk, 3:5], rows[s:s + chunk, 5]
        pred = Perceptron.step(X @ W.T + B)          # same activation as the model
        accs.append((pred == y[:, None]).mean(axis=0))
    return np.concatenate(accs) if accs else np.array([])


def scan_lines(X, y, n_dir=7200):
    """Reference values only (no training): scan line directions on a fine grid (n_dir steps).

    For each unit direction u, the best threshold on u . x is found by sorting.
    Returns (best accuracy any straight line reaches on this sample,
             largest margin, its direction u and threshold c). The margin is half the
    gap between the classes' projections: negative means no line separates them.
    """
    best_acc, best_gamma, best_u, best_c = 0.0, -np.inf, None, None
    n0 = (y == 0).sum()
    for th in np.linspace(0, 2 * np.pi, n_dir, endpoint=False):
        u = np.array([np.cos(th), np.sin(th)])
        p = X @ u
        ys = y[np.argsort(p)]
        # threshold after the k smallest projections: those k -> class 0, the rest -> class 1
        zeros_below = np.concatenate([[0], np.cumsum(ys == 0)])
        ones_above = (len(y) - n0) - (np.arange(len(y) + 1) - zeros_below)
        best_acc = max(best_acc, ((zeros_below + ones_above) / len(y)).max())
        lo1, hi0 = p[y == 1].min(), p[y == 0].max()
        if (lo1 - hi0) / 2 > best_gamma:
            best_gamma, best_u, best_c = (lo1 - hi0) / 2, u, (lo1 + hi0) / 2
    return best_acc, best_gamma, best_u, best_c


# ----------------------------------------------------------------------------- plotting helpers
def scatter_classes(ax, X, y, s=10, alpha=0.55):
    """Scatter both classes with their fixed colors and legend labels."""
    for k in (0, 1):
        ax.scatter(X[y == k, 0], X[y == k, 1], s=s, alpha=alpha, color=CLASS_COLOR[k],
                   edgecolors="none", label=f"Class {k}")


def shade_regions(ax, w, b, xlim, ylim):
    """Lightly tint the half-plane predicted as each class by step(w . x + b)."""
    g1, g2 = np.meshgrid(np.linspace(*xlim, 400), np.linspace(*ylim, 400))
    pred = Perceptron(w, b).predict(np.c_[g1.ravel(), g2.ravel()]).reshape(g1.shape)
    ax.contourf(g1, g2, pred, levels=[-0.5, 0.5, 1.5],
                colors=[CLASS_COLOR[0], CLASS_COLOR[1]], alpha=0.08, zorder=0)


def draw_boundary(ax, w, b, xlim, ylim, **style):
    """Draw the line w1 x1 + w2 x2 + b = 0 clipped to the current axis window."""
    w1, w2 = w
    if abs(w2) >= abs(w1):                         # mostly horizontal: solve for x2
        x1 = np.array(xlim)
        x2 = -(w1 * x1 + b) / w2
    else:                                           # mostly vertical: solve for x1
        x2 = np.array(ylim)
        x1 = -(w2 * x2 + b) / w1
    ax.plot(x1, x2, **style)
    ax.set_xlim(xlim)
    ax.set_ylim(ylim)


def mark_misclassified(ax, X, y, w, b, s=26, lw=1.0, alpha=1.0, label_prefix="Misclassified"):
    """Overlay a black x on every point the weights (w, b) get wrong; return the count."""
    wrong = Perceptron(w, b).predict(X) != y
    ax.scatter(X[wrong, 0], X[wrong, 1], marker="x", s=s, linewidths=lw, color=INK,
               alpha=alpha, zorder=5, label=f"{label_prefix} ({wrong.sum()})")
    return int(wrong.sum())


def data_limits(X, pad=0.6):
    lo, hi = X.min(axis=0) - pad, X.max(axis=0) + pad
    lo_all, hi_all = min(lo), max(hi)               # same range on both axes (equal aspect)
    return (lo_all, hi_all), (lo_all, hi_all)


def save(fig, name):
    FIG_DIR.mkdir(parents=True, exist_ok=True)
    fig.savefig(FIG_DIR / name, bbox_inches="tight")
    plt.close(fig)


def plot_dataset(X, y, title, name, means):
    """Figures 1 and 4: the raw point clouds, one color per class, true means marked."""
    fig, ax = plt.subplots(figsize=(6.2, 5.8))
    scatter_classes(ax, X, y)
    for k, m in enumerate(means):
        ax.scatter(*m, marker="P", s=140, color=CLASS_COLOR[k], edgecolors=INK, linewidths=1.2,
                   zorder=6, label=f"True mean, class {k}: ({m[0]:g}, {m[1]:g})")
    xlim, ylim = data_limits(X)
    ax.set_xlim(xlim)
    ax.set_ylim(ylim)
    ax.set_aspect("equal")
    ax.set_title(title)
    ax.set_xlabel("$x_1$")
    ax.set_ylabel("$x_2$")
    ax.legend(loc="upper left", fontsize=9, framealpha=0.9)
    save(fig, name)

def exercise1(rng):
    print("=" * 78)
    print("EXERCISE 1 -- separable data")
    print("=" * 78)

    # ---------------------------------------------------------------- A: data
    cov1 = [[0.5, 0.0], [0.0, 0.5]]
    X, y = make_two_gaussians(rng, mean0=[1.5, 1.5], mean1=[5.0, 5.0], cov=cov1,
                              n_per_class=N_PER_CLASS)
    describe_data("Ex1 A", X, y)
    plot_dataset(X, y, "Figure 1 — Exercise 1 data (separable)", "fig1.png",
                 means=[(1.5, 1.5), (5.0, 5.0)])

    # ---------------------------------------------------------------- C: train with eta = 0.01
    w0 = rng.normal(0, 0.01, size=2)    # drawn ONCE; the eta = 1.0 run in D2 reuses this w0
    log = Tracer()                      # records which sample triggered each update (for D1)
    model = Perceptron().train(X, y, eta=0.01, max_epochs=MAX_EPOCHS, w0=w0, b0=0.0,
                               on_update=log)
    acc = model.history["accuracy"]
    upd = model.history["updates"]
    acc0 = Perceptron(w0, 0.0).accuracy(X, y)
    out("Ex1 B", f"initial w0 = {fmt_vec(w0, 6)}, b0 = 0, ||w0|| = {np.linalg.norm(w0):.6f}, "
                 f"initial accuracy = {100 * acc0:.2f}%")
    out("Ex1 C", f"final w = {fmt_vec(model.w)}, final b = {model.b:.4f}")
    out("Ex1 C", f"epochs run = {model.epochs_} (last epoch with an update = {model.epochs_ - 1}; "
                 f"epoch {model.epochs_} is the update-free pass that stops training)")
    out("Ex1 C", f"final accuracy = {100 * acc[-1]:.2f}%")
    out("Ex1 C", "accuracy after each epoch = " + ", ".join(f"{100 * a:.2f}%" for a in acc))

    # ---------------------------------------------------------------- D1: updates shrink
    rows = log.array()
    pos = rows[:, 1] + 1                                     # 1-based position inside the epoch
    st_acc = state_accuracies(rows, X, y)
    out("Ex1 D1", f"updates per epoch = {upd} (total {sum(upd)})")
    windows = [(1, 100), (101, 500), (501, 1000), (1001, 2000)]
    counts = [int(((pos >= a) & (pos <= b) & (rows[:, 0] == 1)).sum()) for a, b in windows]
    out("Ex1 D1", "epoch 1 updates by sample position: " +
        ", ".join(f"{a}-{b}: {c}" for (a, b), c in zip(windows, counts)))
    out("Ex1 D1", f"last update at sample position {int(pos.max())} of epoch 1; "
                  f"accuracy after update 9 (position {int(pos[8])}) = {100 * st_acc[8]:.2f}%")
    # Group updates into bursts (consecutive updates less than 30 samples apart).
    breaks = np.flatnonzero(np.diff(pos) >= 30) + 1
    bursts = np.split(np.arange(len(pos)), breaks)
    out("Ex1 D1", f"{len(bursts)} bursts of updates: " + "; ".join(
        f"positions {int(pos[g[0]])}-{int(pos[g[-1]])}: {len(g)} updates, min acc inside "
        f"{100 * st_acc[g].min():.1f}%, acc after {100 * st_acc[g[-1]]:.1f}%" for g in bursts))
    dist = (2 * y - 1) * model.net_input(X) / np.linalg.norm(model.w)
    out("Ex1 D1", f"geometric margin of the eta=0.01 boundary (closest point) = {dist.min():.4f}")

    # ---------------------------------------------------------------- D2: same run, eta = 1.0
    log_big = Tracer()
    model_big = Perceptron().train(X, y, eta=1.0, max_epochs=MAX_EPOCHS, w0=w0, b0=0.0,
                                   on_update=log_big)   # same data, order, w0 and b0

    # Compare boundary DIRECTIONS: unit normal vectors and the angle between them.
    u_small = model.w / np.linalg.norm(model.w)
    u_big = model_big.w / np.linalg.norm(model_big.w)
    angle = np.degrees(np.arccos(np.clip(u_small @ u_big, -1.0, 1.0)))
    acc_big = model_big.history["accuracy"]
    rows_big = log_big.array()
    out("Ex1 D2", f"eta=1.0: final w = {fmt_vec(model_big.w)}, final b = {model_big.b:.4f}")
    out("Ex1 D2", f"eta=1.0: epochs run = {model_big.epochs_}, final accuracy = {100 * acc_big[-1]:.2f}%")
    out("Ex1 D2", f"eta=1.0: updates per epoch = {model_big.history['updates']}, last update at "
                  f"sample position {int(rows_big[:, 1].max()) + 1}")
    out("Ex1 D2", "eta=1.0: accuracy after each epoch = " + ", ".join(f"{100 * a:.2f}%" for a in acc_big))
    out("Ex1 D2", f"unit normal eta=0.01: w/||w|| = {fmt_vec(u_small)}")
    out("Ex1 D2", f"unit normal eta=1.0 : w/||w|| = {fmt_vec(u_big)}")
    out("Ex1 D2", f"angle between the two directions = {angle:.2f} deg")
    for name, m in (("eta=0.01", model), ("eta=1.0 ", model_big)):
        off = -m.b / np.linalg.norm(m.w)          # distance from the origin to the line
        t = -m.b / m.w.sum()                      # where the line crosses the diagonal x1 = x2
        out("Ex1 D2", f"{name}: ||w|| = {np.linalg.norm(m.w):.4f}, distance origin->line = {off:.4f}, "
                      f"crosses x1 = x2 at ({t:.4f}, {t:.4f})")
    out("Ex1 D2", f"effective init ||w0||/eta: eta=0.01 -> {np.linalg.norm(w0) / 0.01:.4f}, "

class Pocket:
    """Pocket algorithm as an on_update hook: keep the best (w, b) seen so far.

    Perceptron.train calls this object after every update. It measures the
    full-dataset accuracy of the CURRENT weights and, if it beats every accuracy
    seen before, copies (w, b) into the pocket. The Perceptron class is untouched.
    """

    def __init__(self, X, y, w0, b0):
        self.X, self.y = X, y
        # The starting weights count as "seen": the pocket starts with them.
        self.w = np.asarray(w0, dtype=float).copy()
        self.b = float(b0)
        self.acc = Perceptron(w0, b0).accuracy(X, y)
        self.epoch = 0                      # epoch in which the pocket was last filled
        self.n_updates = 0                  # updates seen so far (all epochs)
        self.update_index = 0               # global index of the update that filled it
        self.improvements = [(0, self.acc)]

    def __call__(self, model, epoch, i, error):
        self.n_updates += 1
        acc = model.accuracy(self.X, self.y)        # accuracy of the weights right after this update
        if acc > self.acc:                          # strictly better than anything seen before
            self.w, self.b = model.w.copy(), model.b   # <- the only addition: copy into the pocket
            self.acc, self.epoch, self.update_index = acc, epoch, self.n_updates
            self.improvements.append((epoch, acc))

    def best_by_epoch(self, n_epochs):
        """Best-so-far (pocket) accuracy at the end of each epoch 0..n_epochs."""
        best, j, curve = self.improvements[0][1], 0, []
        for e in range(0, n_epochs + 1):
            while j < len(self.improvements) and self.improvements[j][0] <= e:
                best = max(best, self.improvements[j][1])
                j += 1
            curve.append(best)
        return np.array(curve)

    def make_two_gaussians(rng, mean0, mean1, cov, n_per_class):
    """Draw n_per_class 2-D points per class from N(mean_k, cov); return shuffled (X, y).

    X has shape (2 * n_per_class, 2); y holds the labels 0 / 1 as integers.
    """
    X0 = rng.multivariate_normal(mean0, cov, size=n_per_class)  # class 0 cloud
    X1 = rng.multivariate_normal(mean1, cov, size=n_per_class)  # class 1 cloud
    X = np.vstack([X0, X1])
    y = np.concatenate([np.zeros(n_per_class, dtype=int), np.ones(n_per_class, dtype=int)])
    # The draw above lists all class-0 points before all class-1 points. Shuffle ONCE
    # (with the same rng) so the online perceptron does not see 1000 zeros and then
    # 1000 ones; training then visits the samples in this fixed order every epoch.
    order = rng.permutation(len(X))
    return X[order], y[order]

    B — Implement the perceptron

    The model predicts \(\hat y=\operatorname{step}(w\cdot x+b)\), with \(\operatorname{step}(z)=1\) if \(z\ge 0\) and \(0\) otherwise. Labels are \(y\in\{0,1\}\). For each sample, in the fixed shuffled order, it computes \(\hat y\) and applies

    \[ w \leftarrow w + \eta\,(y-\hat y)\,x, \qquad b \leftarrow b + \eta\,(y-\hat y). \]

    The error \(e=y-\hat y\) is \(0\) on a correct prediction, so nothing changes. It is \(+1\) on a missed class-1 point, which pulls \(w\) towards \(x\), and \(-1\) on a false class-1, which pushes \(w\) away from \(x\). That is why the rule is written with \((y-\hat y)\) and not with the \(\pm1\)-label form \(\eta y x\).

    • Initialization. The caller draws w0 = rng.normal(0, 0.01, size=2) from the report's rng (see item C) and passes it to train() with b0 = 0. The class itself never creates randomness.
    • Learning rate. \(\eta = 0.01\).
    • Stopping. Training ends after the first epoch with zero updates, or after max_epochs = 100.
    • Bookkeeping. After every epoch the loop records the full-dataset accuracy and the number of updates (history).
    • Prediction function. Training calls self.predict(x_i), the same function used at inference, so the training rule and the evaluated model can never disagree.

    """Single-layer perceptron written from scratch with NumPy only.

The same class is used, unchanged, by Exercise 1 (separable data) and
Exercise 2 (overlapping data). Exercise 2 adds the pocket algorithm through
the ``on_update`` hook, so not a single line of this file differs between the
two exercises.
"""

import numpy as np


class Perceptron:
    """Binary perceptron with labels in {0, 1}: y_hat = step(w . x + b)."""

    def __init__(self, w=None, b=0.0):
        # Weights can be given directly (e.g. to evaluate saved pocket weights);
        # train() overwrites them with the requested initialization.
        self.w = None if w is None else np.asarray(w, dtype=float).copy()
        self.b = float(b)
        self.history = {"accuracy": [], "updates": []}
        self.epochs_ = 0

    @staticmethod
    def step(z):
        """Heaviside activation: 1 where z >= 0, 0 otherwise (scalar or array)."""
        return np.where(z >= 0, 1, 0)

    def net_input(self, X):
        """Pre-activation z = w . x + b, for one sample (shape (2,)) or many (n, 2)."""
        return X @ self.w + self.b

    def predict(self, X):
        """Class prediction y_hat in {0, 1}."""
        return self.step(self.net_input(X))

    def accuracy(self, X, y):
        """Fraction of samples in (X, y) that the current (w, b) classifies correctly."""
        return float(np.mean(self.predict(X) == y))

    def train(self, X, y, eta, max_epochs, w0, b0=0.0, on_update=None):
        """Online perceptron training on (X, y), visiting samples in the given order.

        eta        -- learning rate.
        max_epochs -- hard cap on the number of passes over the data.
        w0, b0     -- initial weights and bias (w0 is drawn by the caller from the
                      report's single rng, so this class never creates randomness).
        on_update  -- optional callback on_update(model, epoch, i, error), called
                      right after every actual update (Exercise 2: pocket copy).
        """
        # Start from the given initialization (copied so the caller's w0 is untouched).
        self.w = np.asarray(w0, dtype=float).copy()
        self.b = float(b0)
        self.history = {"accuracy": [], "updates": []}

        for epoch in range(1, max_epochs + 1):
            n_updates = 0
            # One epoch = one pass over the samples, always in the same fixed order.
            for i in range(len(X)):
                x_i, y_i = X[i], int(y[i])
                y_hat = int(self.predict(x_i))      # current prediction for this sample
                error = y_i - y_hat                 # 0 if correct, +1 (missed a 1), -1 (false 1)

                if error != 0:
                    # Error-driven update for {0, 1} labels:
                    #   w <- w + eta (y - y_hat) x,   b <- b + eta (y - y_hat)
                    # error = +1 pulls w towards x; error = -1 pushes w away from x.
                    self.w = self.w + eta * error * x_i
                    self.b = self.b + eta * error
                    n_updates += 1
                    if on_update is not None:
                        on_update(self, epoch, i, error)

            # Bookkeeping: full-dataset accuracy and number of updates after every epoch.
            self.history["accuracy"].append(self.accuracy(X, y))
            self.history["updates"].append(n_updates)
            self.epochs_ = epoch

            # Stopping rule: a full pass without a single update means every sample
            # is classified correctly, so the weights can never change again.
            if n_updates == 0:
                break
        return self

    D — Analysis

    D1 — Why separable data converges quickly

    The update term \(\eta\,(y-\hat y)\) is zero for every correctly classified sample. The number of updates in an epoch is therefore exactly the number of mistakes the moving line makes during that pass. Training stops as soon as that number reaches 0.

    • Updates per epoch: 48 in epoch 1, then 0 in epoch 2. Epoch 2 makes no update, so training stops after 2 epochs.
    • Inside epoch 1, updates are dense only at the very start (Figure 3b). Visits 1–100 trigger 23 updates, one every 4 samples. The remaining 1900 visits trigger only 25, one every 76 samples: 3 in visits 101–500, 6 in 501–1000 and 16 in 1001–2000. The last update happens at visit 1457. The remaining 543 visits of epoch 1 and all 2000 visits of epoch 2 change nothing.
    • The line reaches the gap almost immediately. After only 9 updates (visit 13) the accuracy is already 96.40 %. From then on, the only points that can still trigger an update are the few the current line gets wrong, near the gap. They arrive rarely, so updates come in 5 short bursts (visits 1–88, 250–258, 772–797, 1351–1387 and 1435–1457) separated by hundreds of correct, silent samples. Inside a burst the corrections tend to overshoot, because one step of size \(\eta x\) is large next to \(\lVert w\rVert\approx0.04\). Accuracy dips to 50.0 % inside three of the bursts. The bursts hold 3 to 23 updates, and each one ends with the accuracy back at 96.2–100 %. The same overshoot mechanism dominates Exercise 2.
    • Once the line lies inside the empty band, \(y-\hat y=0\) for every sample. The weights then freeze, however many passes follow. That is what epoch 2 shows.

    The convergence theorem makes this precise. With a separating margin \(\gamma>0\) and data radius \(R\), the number of updates is at most \((R/\gamma)^2\). For these data, the widest-margin line found by the scan has a geometric margin of 0.2348. In the augmented space \((x,1)\) that gives \(\gamma=0.0506\) with \(R=9.17\), so the bound is about 32 898 updates. The bound is loose but finite. The observed counts are far below it: 48 updates, or 25 from a zero start (D3). That is because almost every point lies far from any line drawn through the gap: the means are \(7\sigma\) apart.

    What \(\eta\) controls. Every update adds \(\pm\eta x\) to \(w\) and \(\pm\eta\) to \(b\), and \(b_0=0\). After \(k\) updates with errors \(e_j=\pm1\) on samples \(x_{(j)}\):

    \[ w_k = w_0 + \eta\sum_{j=1}^{k} e_j\,x_{(j)}, \qquad b_k = \eta\sum_{j=1}^{k} e_j \quad\Longrightarrow\quad \frac{w_k}{\eta} = \frac{w_0}{\eta} + \sum_{j=1}^{k} e_j\,x_{(j)}, \qquad \frac{b_k}{\eta}=\sum_{j=1}^{k} e_j . \]

    Multiplying \((w,b)\) by a positive constant changes neither the predictions nor the boundary, so the run behaves exactly like a unit-step perceptron started from \(w_0/\eta\). \(\eta\) acts only through the ratio \(w_0/\eta\), i.e. how much the random initialization weighs against the data. That ratio changes which predictions go wrong early, so it changes the path, the number of updates (48 versus 25) and the separating line where training stops. It did not change the epoch count or the final accuracy here (2 epochs and 100 % in both runs).

    • With \(\eta=0.01\), \(\lVert w_0\rVert/\eta = 1.29\), more than a quarter of a typical point (\(\overline{\lVert x\rVert}=4.65\)). Equivalently, each update adds only \(\eta\lVert x\rVert\approx 0.047\), about \(3.6\lVert w_0\rVert\). The random start therefore tips early predictions, and it is still about 30 % of the final norm (\(0.0129\) of \(0.0429\)). The run follows its own path, with 48 updates instead of 25.
    • With \(\eta=1\), \(\lVert w_0\rVert/\eta=0.013\), so the first update (size \(\approx4.65\), about 360 times \(\lVert w_0\rVert\)) wipes the start out. The \(\eta=1.0\) run makes exactly the same 25 updates (same samples, same signs) as a zero start, and its final weights differ from the zero-start weights by exactly \(w_0=[0.009914,\,-0.008270]\) (verified in the code).

    Because the data leave a wide band of separating lines, the perceptron stops at the first line it reaches. \(\eta\), through \(w_0/\eta\), decides which line that is. The bias makes the scaling visible. It only moves in multiples of \(\eta\): \(b=-0.20=-20\eta\), meaning 20 more false-positive than false-negative corrections, versus \(b=-11=-11\eta\).

    D3 — What would have happened from w = 0, b = 0

    Claim. Run the whole training twice from \(w=0,\ b=0\), with the same data and order and with learning rates \(\eta_1\) and \(\eta_2\). Let \(c=\eta_2/\eta_1>0\). Then after every sample visit \(t\) (each visit either updates or not, so the claim covers every update):

    \[ w^{(2)}_t = c\,w^{(1)}_t, \qquad b^{(2)}_t = c\,b^{(1)}_t . \]

    Proof by induction on \(t\).

    Base case (\(t=0\)). \(w^{(2)}_0 = 0 = c\cdot 0 = c\,w^{(1)}_0\), and likewise for \(b\).

    Inductive step. Assume the claim holds at \(t\). Visit \(t+1\) shows both runs the same sample \((x, y)\), because the order is fixed. The two pre-activations are proportional:

    \[ z^{(2)} = w^{(2)}_t\cdot x + b^{(2)}_t = c\,\big(w^{(1)}_t\cdot x + b^{(1)}_t\big) = c\,z^{(1)} . \]

    Since \(c>0\), \(z^{(2)}\ge 0 \iff z^{(1)}\ge 0\), including the tie \(z=0\), because \(c\cdot0=0\). So \(\hat y^{(2)}=\hat y^{(1)}\), and both runs see the same error \(e=y-\hat y\). Then

    \[ \begin{aligned} w^{(2)}_{t+1} &= w^{(2)}_t + \eta_2\,e\,x = c\,w^{(1)}_t + c\,\eta_1\,e\,x = c\,\big(w^{(1)}_t + \eta_1\,e\,x\big) = c\,w^{(1)}_{t+1},\\ b^{(2)}_{t+1} &= b^{(2)}_t + \eta_2\,e = c\,b^{(1)}_t + c\,\eta_1\,e = c\,b^{(1)}_{t+1}. \end{aligned} \]

    So the claim holds at \(t+1\). \(\blacksquare\)

    Consequences.

    1. The inductive step showed that both runs make the same prediction and the same error at every visit. They update on exactly the same samples, so every epoch has the same number of updates. The stopping rule ("an epoch with 0 updates") fires in the same epoch: the epoch count is identical.
    2. The final parameters satisfy \((w^{(2)},b^{(2)})=c\,(w^{(1)},b^{(1)})\) with \(c>0\). The set \(\{x: w\cdot x+b=0\}\) and the sign of \(w\cdot x+b\) are unchanged by a positive factor, so the decision boundary, every prediction and the whole accuracy curve are identical. \(\eta\) only rescales \(w\) and has no effect at all.
    3. With the closed form from D2 and \(w_0=0\): \(w=\eta\sum e_j x_{(j)}\) and \(b=\eta\sum e_j\). The factor \(\eta\) multiplies a sum that does not depend on \(\eta\).

    Why item B forbids the zero start. With \(w_0\neq0\) the base case fails (\(w_0\neq c\,w_0\) for \(c\neq1\)). The effective start \(w_0/\eta\) then depends on \(\eta\), and that is precisely what made the two runs in D2 differ.

    class Pocket:
    """Pocket algorithm as an on_update hook: keep the best (w, b) seen so far.

    Perceptron.train calls this object after every update. It measures the
    full-dataset accuracy of the CURRENT weights and, if it beats every accuracy
    seen before, copies (w, b) into the pocket. The Perceptron class is untouched.
    """

    def __init__(self, X, y, w0, b0):
        self.X, self.y = X, y
        # The starting weights count as "seen": the pocket starts with them.
        self.w = np.asarray(w0, dtype=float).copy()
        self.b = float(b0)
        self.acc = Perceptron(w0, b0).accuracy(X, y)
        self.epoch = 0                      # epoch in which the pocket was last filled
        self.n_updates = 0                  # updates seen so far (all epochs)
        self.update_index = 0               # global index of the update that filled it
        self.improvements = [(0, self.acc)]

    def __call__(self, model, epoch, i, error):
        self.n_updates += 1
        acc = model.accuracy(self.X, self.y)        # accuracy of the weights right after this update
        if acc > self.acc:                          # strictly better than anything seen before
            self.w, self.b = model.w.copy(), model.b   # <- the only addition: copy into the pocket
            self.acc, self.epoch, self.update_index = acc, epoch, self.n_updates
            self.improvements.append((epoch, acc))

    def best_by_epoch(self, n_epochs):
        """Best-so-far (pocket) accuracy at the end of each epoch 0..n_epochs."""
        best, j, curve = self.improvements[0][1], 0, []
        for e in range(0, n_epochs + 1):
            while j < len(self.improvements) and self.improvements[j][0] <= e:
                best = max(best, self.improvements[j][1])
                j += 1
            curve.append(best)
        return np.array(curve)

def draw_boundary(ax, w, b, xlim, ylim, **style):
    """Draw the line w1 x1 + w2 x2 + b = 0 clipped to the current axis window."""
    w1, w2 = w
    if abs(w2) >= abs(w1):                         # mostly horizontal: solve for x2
        x1 = np.array(xlim)
        x2 = -(w1 * x1 + b) / w2
    else:                                           # mostly vertical: solve for x1
        x2 = np.array(ylim)
        x1 = -(w2 * x2 + b) / w1
    ax.plot(x1, x2, **style)
    ax.set_xlim(xlim)
    ax.set_ylim(ylim)

    D — Analysis

    D1 — The gap between the final and the pocket weights

    Where the two boundaries sit (Figure 5).

    • Pocket boundary. It crosses the diagonal at \((3.53,\,3.53)\), 0.04 units from the data center. It predicts class 1 for 47.8 % of the points, with balanced recalls (class 0: 72.9 %, class 1: 68.5 %).
    • Final boundary. It crosses the diagonal at \((2.79,\,2.79)\), which is 0.98 units (0.70 of the cloud's standard deviation of 1.395 along the diagonal) to the class-0 side of the center, even beyond the class-0 mean \((3,3)\). It is also tilted 9.7° off the diagonal direction. It labels 75.8 % of all points as class 1. Class-1 recall is 90.6 %, but class-0 recall is only 39.1 %: most of the blue cloud is on the wrong side.

    Why the loop leaves it there: one mistake moves the line by more than a cloud width. The hint compares the two halves of an update:

    \[ \lvert\Delta b\rvert = \eta = 0.01, \qquad \lVert\Delta w\rVert = \eta\,\lVert x\rVert \approx 0.01\times5.11 = 0.051 . \]

    The data sit about 5 units from the origin. The line's distance from the origin is \(\lvert b\rvert/\lVert w\rVert\), so its position is controlled by the ratio of \(b\) to \(\lVert w\rVert\). That ratio is badly unbalanced:

    • \(b\) barely moves. During epoch 100, \(b\) stayed in \([-0.48,\,-0.40]\), a net drift of 8 steps. Over the whole run there were 38 287 false-negative corrections (\(b\mathrel{+}=\eta\)) and 38 333 false-positive corrections (\(b\mathrel{-}=\eta\)), which almost cancel.
    • \(\lVert w\rVert\) swings wildly. Over the same epoch it ranged over \([0.0083,\,0.1820]\), because each step of size \(0.051\) is comparable to \(\lVert w\rVert\) itself.
    • So the line passes through the center only near one value of \(\lVert w\rVert\). With \(b\approx-0.46\), that value is \(\lVert w\rVert\approx0.46/4.95=0.093\), and a single update changes \(w\) by about \(0.051\), more than half of it. The line is thrown back and forth: during epoch 100 its distance from the origin, \(-b/\lVert w\rVert\), ranged from 3.00 to 12.15 units (5th–95th percentile), while the data center sits 4.95 units from the origin.
    • The same effect, seen from the data. One update changes the score of the center by \(\eta\,(x\cdot c+1)\approx0.255\) on average, because \(x\cdot c\approx25\) dwarfs the \(+1\) that comes from \(b\). The score only varies by \(\lVert w\rVert\approx0.095\) per unit of distance, so one mistake shifts the boundary by about \(0.255/0.095\approx2.7\) units along its normal.
    • Measured. In epoch 100 the median jump of the center's signed distance to the line was 2.71 units per update, about 1.9 cloud standard deviations. The 5–95 % range of that distance was \([-8.90,\ +1.81]\). In one epoch, the line goes from far beyond the class-1 cloud, where it labels almost everything 0, to the class-0 side and back.

    Since the classes overlap, every position of the line leaves misclassified points on both sides. Mistakes keep arriving from both classes, ≈383 from each (382.9 on class-1 points and 383.3 on class-0 points per epoch on average, ≈766 updates per epoch in total), and each one kicks the line roughly two standard deviations. The "final" weights are simply wherever the last kick of epoch 100 left the line. In this run, that was the class-0 side.

    The final accuracy is a lottery; the pocket is the best ticket. Across all 76 620 states the weights visit, the accuracy has a median of 60.8 %, a 5th percentile of 50.0 % and a 95th percentile of 69.7 %. A quarter of the states (24.7 %) are below 55 %, and only 2.3 % reach 70 %. The end-of-epoch snapshots in Figure 6 range from 60.80 % (epoch 10) to 68.30 % (epoch 88), with a mean of 64.60 %. Our 64.85 % is a typical draw. The pocket scores every visited state and keeps the maximum, 70.70 %; the code asserts that it equals the best of the 76 620 states. The 5.85-point gap is therefore the gap between the best visited state and a typical end-of-epoch state (mean 64.60 % at the epoch ends; median 60.8 % over all visited states).

    Sample order decides the draw, not the outcome. As a side run, I re-sort the same shuffled samples by class: all class 0 first, then all class 1, keeping the shuffled order within each class. This reproduces the class-block structure of the raw generation order. Now the last 1000 visits of every epoch are class-1 points, so every update there is an \(e=+1\) correction. Each of those corrections adds \(\approx\eta\lVert x\rVert\approx0.05\) to \(w\), along the direction of the cloud, but only \(\eta=0.01\) to \(b\). This is the statement's hint. The class-1 scores \(w\cdot x+b\) therefore rise much faster through \(w\) than the bias can offset, and the line is dragged towards the origin.

    • The final weights are \(w=[0.0457,\ 0.0374]\) with only \(b=-0.0600\). The line crosses the diagonal at \((0.72,\,0.72)\), 1.02 units from the origin.
    • That is 3.91 units from the data center, about 2.8 cloud standard deviations, on the class-0 side: completely outside the cloud.
    • The final weights label 99.8 % of the points as class 1 and score 50.25 %. That is the "near 50 %" scenario the statement warns about.

    Shuffling, as done here, makes the snapshot random instead of systematically bad. It does not stop the oscillation.

    D2 — Figure 3 vs. Figure 6: what the convergence theorem guarantees

    • Figure 3 (separable). Accuracy jumps from 61.50 % to 100 % within epoch 1 and stays there. Updates per epoch fall from 48 to 0, and training stops by itself after epoch 2.
    • Figure 6 (overlapping). The current weights never settle. End-of-epoch accuracy wanders between 60.80 % and 68.30 %, and inside every epoch the accuracy after individual updates spans about 50–70 % (grey band). Epoch 100 still makes 757 updates, and the stopping rule never fires. The only flat curve is the green pocket staircase, flat after epoch 40. It is monotone by construction (a running maximum), not because training converged.

    The perceptron convergence theorem (Novikoff). Write labels as \(s_i=2y_i-1\in\{-1,+1\}\) and use augmented points \(\tilde x_i=(x_i,1)\) with \(\lVert\tilde x_i\rVert\le R\). Suppose some unit vector \(u^{\star}\) separates the data with a positive margin, \(s_i\,u^{\star}\cdot\tilde x_i\ge\gamma>0\) for all \(i\). Then, from a zero start, the perceptron makes at most \((R/\gamma)^2\) updates, for any sample order and any \(\eta\). After that it classifies every point correctly and stops.

    Why. Each update raises \(u^{\star}\cdot\tilde w\) by at least \(\eta\gamma\) and raises \(\lVert\tilde w\rVert^2\) by at most \(\eta^2R^2\). So \(k\eta\gamma\le\lVert\tilde w_k\rVert\le\eta R\sqrt k\), which gives \(k\le(R/\gamma)^2\).

    • Exercise 1. \(\gamma=0.0506\) and \(R=9.17\), so the bound is about 32 898 updates: finite, and satisfied with room to spare (48 updates).
    • Exercise 2. The assumption that breaks is linear separability, i.e. the existence of a margin \(\gamma>0\). The best line still misclassifies 584 points (70.80 %). The scan finds the two classes' projections overlapping in every direction: the widest "margin" is \(-3.16<0\). No \(\gamma>0\) exists, so the bound is infinite and the theorem guarantees nothing. It guarantees neither convergence nor a good last iterate.
    • What does hold here. The companion result for non-separable data, the perceptron cycling theorem (Minsky & Papert; Block & Levin), says only that the weights stay bounded. That is what we see: \(\lVert w\rVert\) never exceeds 0.1875, and its mean is 0.0945 in epochs 1–50 versus 0.0953 in epochs 51–100. The weights wander in a bounded region forever instead of converging.

    D3 — Would more epochs, or a smaller η, fix it?

    No, and the update rule shows why.

    More epochs.

    • The loop stops only after a pass in which every \(y-\hat y=0\). That pass would require a line that classifies all 2000 points correctly, and none exists. Every epoch, forever, contains mistakes (739–822 per epoch in this run), and every mistake moves the line.
    • The step does not shrink with time. The jump per mistake is \(\approx\eta(x\cdot c+1)/\lVert w\rVert\), and \(\lVert w\rVert\) does not grow: it stays bounded around 0.095, as D2 showed. Nothing in the rule decays, accumulates or averages.
    • So epoch 1000 is statistically the same as epoch 100: the last iterate is still a random point of the same bounded oscillation. More epochs only buy more lottery tickets, which helps the pocket a little and the final weights not at all.

    A smaller \(\eta\).

    • The rule is homogeneous in \(\eta\): every update adds \(\eta\) times \((e\,x,\ e)\). Once the accumulated updates outweigh \(w_0\), \((w,b)/\eta\) follows the same \(\eta\)-independent trajectory. This is the zero-start argument of Exercise 1-D3, applied after the brief transient in which \(w_0/\eta\) still matters.
    • \(\lVert\Delta w\rVert\), \(\lvert\Delta b\rvert\) and \(\lVert w\rVert\) all scale by \(\eta\). The geometric jump of the line, \(\eta(x\cdot c+1)/\lVert w\rVert\), is unchanged, and so is the 5 : 1 ratio between \(\lVert\Delta w\rVert\) and \(\lvert\Delta b\rvert\). That ratio comes from \(\lVert x\rVert\approx5\), a property of the data, not of \(\eta\).
    • A smaller \(\eta\) therefore rescales the weights without making the steps any finer relative to the cloud. The only other effect is to make the random \(w_0\) matter for longer.

    What does help is changing what we keep: the pocket, or, for example, averaging the iterates. Changing the rule or loss would also help. Neither more time nor a smaller step does.

    Confirmation runs (consistent with the argument, not a replacement for it).

    • 1000 epochs, \(\eta=0.01\). The final accuracy is 65.05 %. Epochs 901–1000 average 64.80 % (range 54.55–66.90 %), and epoch 1000 still makes 759 updates.
    • \(\eta=0.001\), 100 epochs. The final accuracy is 68.25 %. Epochs 51–100 average 64.65 % (range 62.80–68.25 %), and epoch 100 makes 776 updates.

    Both runs land in the same band as the original run (end-of-epoch mean 64.60 %). Neither settles.
