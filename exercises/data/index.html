    1. Data

    This report generates and measures synthetic point clouds (Exercises 1 and 2) and prepares a real Kaggle dataset for a tanh network (Exercise 3). The thread is the spread of the data: how far a cloud extends, in which direction, and what that does to the boundaries a network would need. Statement: Exercises → 1. Data (2026.2).

    How to re-run. From the repository root:

    python docs/exercises/data/code/main.py

    The script regenerates every figure in figures/ and prints every number quoted below, one labelled line per number. Exercise 3 needs Kaggle's train.csv (see Getting the data); without it the script still runs Exercises 1 and 2 and prints the download instructions.

    def draw_noise(rng):
    """Draw the standard-normal noise z ~ N(0, 1) for every class, point and axis.

    Shape (4, 100, 2). Each axis gets its own independent draw, so the clouds
    are independent per-axis Gaussians (diagonal covariance), as specified.
    """
    return rng.standard_normal((N_CLASSES, N_PER_CLASS, 2))


def make_clouds(noise, scale=1.0):
    """Turn the noise into labelled points: x = mu_k + (s * sigma_k) * z.

    Broadcasting applies class k's mean and (scaled) standard deviation to all
    100 points of that class. Returns X with shape (400, 2) and integer labels y.
    """
    points = MEANS[:, None, :] + scale * STDS[:, None, :] * noise
    X = points.reshape(-1, 2)                                  # stack the 4 classes
    y = np.repeat(np.arange(N_CLASSES), N_PER_CLASS)           # 0...0, 1...1, ...
    return X, y

    def separation_ratios(scale=1.0):
    """r_ij = ||mu_i - mu_j|| / (sigma_bar_i + sigma_bar_j) for the 6 pairs.

    Uses the SPECIFIED parameters (not sample estimates). sigma_bar_k is the
    average of the two axis standard deviations of class k, times the scale s,
    so r_ij(s) = r_ij(1) / s.
    """
    sigma_bar = scale * STDS.mean(axis=1)              # (sigma_x + sigma_y) / 2
    rows = []
    for i, j in combinations(range(N_CLASSES), 2):     # (0,1), (0,2), ..., (2,3)
        dist = np.linalg.norm(MEANS[i] - MEANS[j])
        rows.append((i, j, dist, sigma_bar[i] + sigma_bar[j],
                     dist / (sigma_bar[i] + sigma_bar[j])))
    return rows


def directional_ratio(i, j, scale=1.0):
    """Variant of r_ij that uses the spread ALONG the line joining the two centers.

    For a class with per-axis stds (sx, sy), the std of its projection onto the
    unit vector d = (dx, dy) is sqrt(dx^2 sx^2 + dy^2 sy^2). r_ij averages the
    two axes instead, so it ignores the direction in which each cloud is spread.
    """
    d = (MEANS[j] - MEANS[i]) / np.linalg.norm(MEANS[j] - MEANS[i])
    spread = lambda k: scale * np.sqrt(np.sum(d ** 2 * STDS[k] ** 2))  # noqa: E731
    return np.linalg.norm(MEANS[j] - MEANS[i]) / (spread(i) + spread(j))

    def nearest_center(X):
    """Index of the closest TRUE class mean for every point (Euclidean)."""
    # (n, 1, 2) - (1, 4, 2) -> (n, 4, 2) differences -> (n, 4) distances.
    dists = np.linalg.norm(X[:, None, :] - MEANS[None, :, :], axis=2)
    return dists.argmin(axis=1)


def mixing_rate(X, y):
    """Fraction of points whose nearest center is NOT the mean of their class."""
    return float(np.mean(nearest_center(X) != y))


def mixing_matrix(X, y):
    """Counts M[true class, nearest-center class]; off-diagonal = mixed points."""
    M = np.zeros((N_CLASSES, N_CLASSES), dtype=int)
    np.add.at(M, (y, nearest_center(X)), 1)
    return M

    4. Figure 3 and the separability threshold. The mixing rate counts errors of one particular set of straight lines: the nearest-center boundaries. To answer "from which \(s\) on can the clouds no longer be separated by straight lines?" exactly, the code also tests every pair of classes: two finite point sets can be split by a single straight line if and only if their convex hulls do not intersect. The test is pure geometry on the sampled points; nothing is fitted. If every pair is separable, a set of straight lines (one per pair, with one-vs-one voting) classifies all 400 points correctly.

    \(s\) Pairs that no straight line separates Smallest ratio \(r_{01}\)
    0.5 none 2.65
    1.0 (0, 1), (1, 2) 1.33
    2.0 (0, 1), (0, 2), (1, 2) 0.66
    4.0 (0, 1), (0, 2), (1, 2), (1, 3), (2, 3) 0.33

    From \(s = 1\) on, the clouds can no longer be separated by straight lines. At \(s = 0.5\) the nearest-center lines still misplace one point (0.25%), but the hull test shows a slightly moved line would fix it: all 6 pairs are linearly separable. At \(s = 1\) the convex hulls of classes 0 and 1 (and of 1 and 2) intersect, so any straight boundary between them misclassifies at least one point, and the mixing rate is 5.00%. At that point the smallest ratio is \(r_{01} = 1.33\) (it was 2.65 at \(s = 0.5\)). The distance between the centers of classes 0 and 1 (4.24) is then only 1.33 times the sum of their average spreads (3.20), so the two clouds meet roughly 1.3 average spreads from each center, and with 100 points per class a handful of points of each class reach past that meeting zone: the 14 points 0↔1 of the mixing table. \(r_{01}\) crosses 1 at \(s = 1.33\); at \(s = 2\) it is 0.66, the distance between the centers is smaller than the sum of the spreads, and the mixing rate jumps to 20.25%.

    Gaussian tails never end, so in theory any two of these clouds overlap at every \(s\), and a large enough sample is never linearly separable. The threshold \(s = 1\) describes these 100-point samples. With more points per class the extreme tails would reach further and separability would be lost at a smaller \(s\).

    \(r_{ij}\) is a summary, not an exact criterion, because it averages the two axis spreads and ignores their direction. Pair (1, 2) already fails at \(s = 1\) although \(r_{12} = 2.38\), while pair (0, 2), with almost the same \(r_{02} = 2.48\), is still separable at \(s = 1\) and fails only at \(s = 2\). Measuring each cloud's spread along the line joining the two centers (unit vector \(d\)), \(\sigma_{k,\text{dir}} = \sqrt{d_x^2\sigma_{k,x}^2 + d_y^2\sigma_{k,y}^2}\), explains the difference. That ratio is 2.21 for (1, 2), because class 1 is widest along \(y\), the direction of \(\mu_2 - \mu_1\). It is 3.17 for (0, 2), because class 0's large \(\sigma_y = 2.5\) is almost perpendicular to \(\mu_2 - \mu_0\). For (0, 1) it is 1.23.

    def convex_hull(P):
    """Vertices of the convex hull of 2-D points (Andrew's monotone chain)."""
    P = np.unique(P, axis=0)                 # sorted by x, then y

    def cross(o, a, b):                      # > 0 when o -> a -> b turns left
        return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

    lower, upper = [], []
    for p in P:                              # lower chain, left to right
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)
    for p in P[::-1]:                        # upper chain, right to left
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return np.array(lower[:-1] + upper[:-1])


def linearly_separable(A, B):
    """Exact test: can ONE straight line put all of A on one side and all of B on the other?

    Two finite point sets are linearly separable iff their convex hulls do not
    intersect, and two convex polygons are disjoint iff the normal of one of
    their edges is a separating axis (separating-axis theorem). So we project
    both sets onto every edge normal of both hulls and look for a gap.
    Pure geometry on the sampled points: nothing is fitted or trained.
    """
    for H in (convex_hull(A), convex_hull(B)):
        edges = np.roll(H, -1, axis=0) - H           # edge vectors of the hull
        normals = np.c_[-edges[:, 1], edges[:, 0]]   # one normal per edge
        pa, pb = A @ normals.T, B @ normals.T        # projections, (n, n_edges)
        gap = (pa.max(axis=0) < pb.min(axis=0)) | (pb.max(axis=0) < pa.min(axis=0))
        if gap.any():
            return True
    return False

    def voronoi_edges(xlim, ylim, n=4000):
    """Pieces of the perpendicular bisectors that separate neighbouring means.

    For each pair (i, j) the bisector is the set of points equidistant to mu_i
    and mu_j. We sample that line densely inside the plot window and keep only
    the samples that are at least as close to mu_i (= mu_j) as to every other
    mean: those samples form the boundary segment between the two regions.
    Pairs whose bisector never survives (non-neighbours) are skipped.
    """
    edges = {}
    for i, j in combinations(range(N_CLASSES), 2):
        mid = (MEANS[i] + MEANS[j]) / 2
        d = MEANS[j] - MEANS[i]
        direction = np.array([-d[1], d[0]]) / np.linalg.norm(d)   # along the bisector
        t = np.linspace(-60, 60, n)
        pts = mid + t[:, None] * direction
        inside = ((pts[:, 0] >= xlim[0]) & (pts[:, 0] <= xlim[1]) &
                  (pts[:, 1] >= ylim[0]) & (pts[:, 1] <= ylim[1]))
        dists = np.linalg.norm(pts[:, None, :] - MEANS[None], axis=2)
        keep = inside & (dists[:, i] <= dists.min(axis=1) + 1e-9)
        if keep.any():
            edges[(i, j)] = pts[keep]
    return edges

    rho = rng.normal(rho_mean, rho_std, size=n)          # one radius per point
    return rho[:, None] * u, u

    D — Analysis

    1. Coincident centers, separated radii: what about a hyperplane? A hyperplane classifier \(\operatorname{sign}(w^\top x + b)\) only looks at the projection \(w^\top x\). In Dataset II both classes are centered at the same point (distance 0.2614) and are rotation-invariant. Along any direction \(w\), the core (radius \(\approx 2\)) projects into about \([-2, 2]\) and the shell (radius \(\approx 5\)) into about \([-5, 5]\), both centered on 0, so the shell's projection covers the core's from both sides. Shifting or tilting the hyperplane only trades errors on one side for errors on the other. The radius histograms, in contrast, are disjoint (gap 2.990 → 3.850). The separating information is in the norm, a non-linear function of \(x\), not in any linear combination of the coordinates.

    The best accuracy any hyperplane can reach is computable. One coordinate of a uniform direction on the sphere of \(\mathbb R^5\) has density \(\tfrac34(1-a^2)\) on \([-1, 1]\). Scanning the offset \(t\) of the rule "shell if \(w^\top x > t\)" for ideal radii 2 and 5 gives at best 62.01% (\(t = 1.601\)), against 50% for guessing. Applying that rule to the sample with \(w = e_1\) gives 61.50%, while \(\lVert x\rVert^2\) gets 100% (below). For contrast, on Dataset I the hyperplane that bisects the specified means \(\mu_A\) and \(\mu_B\), a linear rule with nothing fitted, already classifies 89.60% of the points.

    def f_shells(X):
    """Hand-written separator of Dataset II: f(x) = sum_i x_i^2 - 12.25.

    f(x) < 0 -> class C (core), f(x) > 0 -> class D (shell). It is linear in
    the squared inputs x_i^2 but quadratic in the original inputs x_i.
    """
    return np.sum(X ** 2, axis=1) - SQ_THRESHOLD


def best_hyperplane_accuracy_shells(r_core=RHO_C[0], r_shell=RHO_D[0]):
    """Best accuracy ANY hyperplane can reach on ideal shells (radii exactly 2 and 5).

    Both classes are rotation-invariant, so every direction w is equivalent and
    only the offset t of the rule "shell if w.x > t" matters. For u uniform on
    the unit sphere of R^5, one coordinate has density (3/4)(1 - a^2) on [-1, 1],
    hence CDF F(a) = 1/2 + (3/4)(a - a^3/3). A point of radius r lands on the
    "shell" side when u_1 > t / r, so
        accuracy(t) = [P(shell side | shell) + P(core side | core)] / 2
                    = [1 - F(t / r_shell) + F(t / r_core)] / 2.
    This is a property of the distributions, not of the sample: more data
    cannot push a hyperplane above this value.
    """
    def F(a):
        a = np.clip(a, -1.0, 1.0)
        return 0.5 + 0.75 * (a - a ** 3 / 3)
    t = np.linspace(-r_shell, r_shell, 20001)
    acc = 0.5 * ((1 - F(t / r_shell)) + F(t / r_core))
    k = int(acc.argmax())
    return float(acc[k]), float(t[k])

    2. Why no linear boundary works, however much data is collected. Two finite sets are linearly separable if and only if their convex hulls do not intersect. The shell surrounds the core in every direction of \(\mathbb R^5\), so every core point is a convex combination of shell points: the core lies inside the convex hull of the shell, and no hyperplane can have all core points on one side and all shell points on the other. Collecting more data does not help. More shell points cover the sphere more densely, so the shell's hull approaches the full ball of radius \(\approx 5\) and the core sits inside it even more surely. The 62.01% ceiling above is a property of the distributions, not of the sample size; more data only estimates it more precisely. This is a limit of the model family (hyperplanes), not a lack of data.

    3. PCA is linear: does a mixed 2-D projection prove inseparability? No. A projection can only lose separability, never create it. PCA is unsupervised: it keeps the directions of largest variance, not the directions that separate the classes, and it discards the rest. Points that differ only in the discarded directions collapse onto each other. My results show this directly. In Figure 4 Dataset II looks mixed: 61.00% of the shell points fall inside the core's 2-D disk, and the two components keep only 42.15% of the variance. Yet in the original 5-D space the classes are perfectly separable by a simple function of the inputs:

    \[ f(x) = \lVert x\rVert^2 - 12.25 = \sum_{i=1}^{5} x_i^2 - 12.25,\qquad \hat y = \begin{cases} \text{D (shell)} & f(x) > 0 \\ \text{C (core)} & f(x) < 0 \end{cases} \]

    The threshold comes from the specified radii, not from the data: halfway between 2 and 5 is 3.5, and \(3.5^2 = 12.25\). This rule classifies 1000 of 1000 points correctly (100%). It also has a wide margin: the largest \(\lVert x\rVert^2\) in the core is 8.941 and the smallest in the shell is 14.823. \(f\) is quadratic in \(x\) but linear in the features \(x_i^2\). In the lifted space \(z = (x_1^2, \dots, x_5^2)\) it is a hyperplane. That non-linear change of representation is exactly what a hidden layer can learn and a Perceptron cannot.

    def split(df, seed):
    """Stratified 80/20 split - the FIRST operation after loading.

    stratify=y keeps the share of Transported identical in both parts; the fixed
    seed makes the split reproducible. Nothing has been imputed, encoded or
    scaled yet, so no test-set information can leak into the transformers.
    """
    X = df.drop(columns=[TARGET])
    y = df[TARGET].astype(int)               # True -> 1, False -> 0
    return train_test_split(X, y, test_size=TEST_SIZE, stratify=y, random_state=seed)

    2. Why the split comes before imputation and scaling. The test set stands in for future passengers the network has never seen, so any statistic computed with it (an imputation median, a scaling mean or standard deviation, the list of categories) would carry information about those rows into training. Splitting first and fitting every transformer on the training part only transforms the test rows exactly as new data would be. Otherwise the test score is optimistically biased (data leakage) and stops being a trustworthy estimate of generalization.

def add_total_spend(X):
    """Append TotalSpend = RoomService + FoodCourt + ShoppingMall + Spa + VRDeck.

    Runs AFTER imputation, so a single missing spend no longer turns the sum
    into NaN. It is a row-wise sum: there is nothing to fit.
    """
    X = np.asarray(X, dtype=float)
    return np.column_stack([X, X.sum(axis=1)])


def _total_spend_names(transformer, input_features):
    """Column names after add_total_spend (keeps get_feature_names_out working)."""
    return np.append(np.asarray(input_features, dtype=object), "TotalSpend")


def build_preprocessor():
    """One ColumnTransformer = three per-column-type pipelines.

    Age      : median imputation -> standardization
    Spending : median imputation -> + TotalSpend -> log1p -> standardization
    Category : most-frequent imputation -> one-hot (unknown -> all zeros)
    Columns not listed (the identifiers, if still present) are dropped.
    """
    age_pipe = Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("scale", StandardScaler()),                 # (x - mean_train) / std_train
    ])
    spend_pipe = Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("total", FunctionTransformer(add_total_spend,
                                      feature_names_out=_total_spend_names)),
        ("log1p", FunctionTransformer(np.log1p, feature_names_out="one-to-one")),
        ("scale", StandardScaler()),
    ])
    cat_pipe = Pipeline([
        ("impute", SimpleImputer(strategy="most_frequent")),
        ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
    ])
    return ColumnTransformer(
        [("age", age_pipe, ["Age"]),
         ("spend", spend_pipe, SPEND_COLS),
         ("cat", cat_pipe, CAT_COLS)],
        remainder="drop",
        verbose_feature_names_out=False,
    )

    def preprocess(X_train, X_test):
    """Fit every transformer on the TRAINING split, then apply it to both."""
    X_train, X_test = drop_identifiers(X_train), drop_identifiers(X_test)
    pre = build_preprocessor()
    pre.fit(X_train)                       # medians, modes, categories, means, stds
    Xtr = pre.transform(X_train)           # learned from train only ...

    names = list(pre.get_feature_names_out())
    return pre, Xtr, Xte, names

    1. Missing data, one strategy per column type (all imputers fitted on train, applied to test). Every column misses only 2.06–2.50% of its values (A.4), so a single, simple imputation per type adds little bias. A model-based imputer would add complexity for about 2% of the cells.

    • Numerical → median (SimpleImputer(strategy="median")).
      • For the five spending columns the learned training medians are all 0.0, so a missing spend becomes "spent nothing", by far the most common value: 64.0% of the observed FoodCourt values in train are 0 (Figure 6).
      • The mean would be the wrong choice here. It is dragged up by the tail (471.80 for FoodCourt on train, with skewness 6.84), so it would invent a 471.80-credit FoodCourt bill for passengers who most likely spent nothing.
      • For Age the learned median is 27.00. Age is only mildly skewed (mean 28.83 vs. median 27.00, skewness 0.42), so mean and median are close. The median is kept for robustness and consistency, and it is a real, typical age.
    • Categorical → most frequent (SimpleImputer(strategy="most_frequent")).
      • The learned modes are HomePlanet = Earth, CryoSleep = False, Destination = TRAPPIST-1e and VIP = False.
      • The mode is the only "central value" a category has, and it keeps every one-hot block a valid indicator with exactly one active column.
      • A separate "missing" level would add four columns, one per feature, for about 2% of the rows each, so the mode is the cheaper choice at this missingness.
      • Imputation runs before encoding, so a NaN never reaches the encoder.

    2. Categorical → numbers: one-hot encoding. HomePlanet, CryoSleep, Destination and VIP are one-hot encoded with OneHotEncoder(handle_unknown="ignore"). The categories learned on train are Earth/Europa/Mars, False/True, 55 Cancri e/PSO J318.5-22/TRAPPIST-1e and False/True, which gives 10 one-hot columns. Each category becomes a 0/1 column, so the network sees no artificial order (Earth < Europa < Mars would be meaningless).

    A category that appears only in the test set is ignored: its whole block of columns is set to 0, with no error and no new column. The row then simply carries no information for that feature, and the matrix keeps the same shape as in training. The code demonstrates it by replacing a test row's HomePlanet with the unseen value "Pluto": it encodes as HomePlanet_Earth = HomePlanet_Europa = HomePlanet_Mars = 0. In the actual split no test category is unseen; every value of the four columns in the 1739 test rows also occurs in train.

    3. Feature engineering: TotalSpend.

    \[ \text{TotalSpend} = \text{RoomService} + \text{FoodCourt} + \text{ShoppingMall} + \text{Spa} + \text{VRDeck} \]

    It is computed inside the spending pipeline after median imputation, so one missing column no longer turns the sum into NaN. It is a row-wise sum with nothing to fit, and it summarizes the overall spending level in one feature. PassengerId, Cabin and Name are dropped explicitly by drop_identifiers() before fitting. They are identifiers or near-unique strings that a network could only memorize.

    4. Heavy tails: \(\log(1+x)\). The five spending columns and TotalSpend go through np.log1p. \(\log(1+x)\) maps 0 to 0, stays defined for zero spending (where \(\log x\) would be \(-\infty\)), and compresses large values multiplicatively: 100 becomes 4.6, 10 000 becomes 9.2. The before/after histogram is Figure 6 (item D.1). For FoodCourt on the training split, the skewness drops from 6.84 (raw) to 1.14 (after \(\log(1+x)\)), and the maximum shrinks from 27723 credits to 10.23.

    Why it helps a network with tanh. \(\tanh(z)\) is only sensitive for \(|z|\) up to about 2–3. Beyond that it saturates at ±1 and its derivative \(1 - \tanh^2(z)\) is almost 0, so the weights feeding that unit stop learning. The code measures what standardizing the raw columns would do: the largest standardized value on the training split would be:

    def tail_compression(X_train, Xtr, names):
    """Largest standardized value of each spending column, without vs. with log1p.

    "Without": impute with the training median, then standardize the raw column.
    "With": the actual pipeline output (impute -> log1p -> standardize).
    A value of z means "z training standard deviations above the mean"; the
    larger it is, the deeper that passenger pushes a tanh unit into saturation.
    """
    out = {}
    for col in SPEND_COLS:
        raw = X_train[col].fillna(X_train[col].median())
        z_raw = ((raw - raw.mean()) / raw.std(ddof=0)).max()
        out[col] = (float(z_raw), float(Xtr[:, names.index(col)].max()))
    return out

    5. Scaling: standardization (StandardScaler, \(z = (x - \text{mean}_\text{train})/\text{std}_\text{train}\)) on the 7 numerical columns: Age, the five log-spends and log-TotalSpend. The 0/1 one-hot columns are already on a tanh-compatible scale and are left as they are. Why standardization rather than min-max to \([-1, 1]\):

    • It centers every input at 0, where tanh is steepest (\(\tanh'(0) = 1\)).
    • It gives unit variance, the assumption behind the usual Xavier/Glorot initialization, so the first pre-activations start around order 1.
    • Min-max lets the extremes define the whole range: the smallest and largest training values set the scale, so a single outlier squeezes everyone else into a narrow band, and test values outside the training range break the \([-1, 1]\) promise anyway.

    The resulting range is not \([-1, 1]\), but the values are of order 1, which is what tanh needs.

    3. Which decision would most affect training? The \(\log(1+x)\) on the spending columns, together with scaling them. Six of the seven numerical inputs are spending features, and without the log their largest standardized values would be 16.80 to 37.81 standard deviations from the mean, against 2.82 to 3.32 with it. Those few passengers would push tanh units into saturation, where the gradient vanishes. They would also dominate the weighted sums and the loss gradient early in training, which forces a small learning rate and slows learning for everyone else. The log turns a multiplicative scale (tens vs. thousands of credits) into an additive one that a weighted sum can use.

    What the log does not fix is the zero spike: 64.8% of the training FoodCourt values remain one separate bar. The data hint at a better encoding. All 3037 passengers with CryoSleep = True have a largest recorded spend of 0.0, since cryosleepers are confined to their cabins. A binary "spent anything" flag, or a network that learns this CryoSleep–spending link, could exploit that structure. By comparison, the imputation choices touch only 2.06–2.50% of each column, and one-hot encoding four low-cardinality columns (10 columns in total) is standard and low-risk.
